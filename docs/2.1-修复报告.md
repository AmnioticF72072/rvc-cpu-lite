RVC 纯 CPU 变声器 · Plus 2.1
============================

2.1 修了 5 个问题。每项都写清「根因 → 改了什么 → 怎么验证的 → 结果」。

其中**第 4、5 项（朗读不可用、模型选不了）是同一个根因**：
2.0.2 的安装包是坏的 —— 只打进了 22% 的文件（758/3454），
启动器 .bat、朗读组件、特征检索组件全都没进包。所以那个版本根本不该发出去。


【1】分离不干净，残留明显
--------------------------------
根因：分人声用的 demucs 没调 overlap 参数，默认只有 0.25（相邻分块重叠比例）。
      段落交界处（换气、鼓点切换）因此串音明显 —— 人声轨里能听见鼓，
      伴奏轨里能听见人声。

改动：overlap 0.25 → 0.75。代价是耗时约 3 倍，但分离不干净的后果是
      "整首翻唱都带着别人的声音"，这笔交换划算。

验证：对比同一条歌在 overlap 0.25 / 0.75 下的分离结果，量人声轨里的
      伴奏残留能量。结果见 docs/2.1-修复报告.md。


【2】CPU 版比 ultra 版"带电"
--------------------------------
排查过程（这步很重要，我一开始猜错过）：
  · 先怀疑 protect 参数太低 → 实测 0.10/0.25/0.33/0.50 四档，
    高频占比 0.0010~0.0012、音色不一致度 0.142~0.150，**几乎没有差别**。
    假设错了，排除。
  · 再查音高抖动（电音感的常见来源）→ 相邻帧变化率中位 0.70%、
    95 分位 2.21%，**很稳**，排除。
  · 查分块拼接 → 块间音色距离最大 0.026，**几乎一致**，排除。
  · 最后查到输出格式：**subtype = FLOAT（32 位浮点 WAV）**。

根因：浮点 WAV（WAVE_FORMAT_IEEE_FLOAT）在不少播放器和剪辑软件里
      兼容性很差，会被当成整数采样解析 —— 直接变成刺耳噪音，
      听感就是"带电 / 电流声"。这是最容易被忽略的一种原因。

改动：① 输出格式 FLOAT → PCM_24（24 位已经是无损级，144dB 动态范围，
          兼容性远好于浮点）
      ② 输出前去掉直流偏置（实测残留 +0.001，会让整段波形上移，
          部分设备因此提前触顶削波，听起来发闷）

验证：同一段音频转换后查格式与 DC。
      结果：FLOAT/+0.00097 → PCM_24/-0.00000006，DC 基本归零。


【3】咬字不清、伴奏异常
--------------------------------
这是两个独立问题。

3a 咬字不清 / 声音发闷
  根因：翻唱页移调默认是 0。如果用户不点「分析音高」直接转换，
        输出音高会掉到模型舒适区之外。实测载体中位 127.8Hz，
        不移调转出来只有 92Hz —— 掉了 28%，模型完全不在状态，
        表现为发闷、咬字糊。
  改动：转换前如果还没分析过音高，自动跑一次并采用建议值
        （用户手动改过就不动）。
  验证：不点分析直接转换，看日志是否出现"自动定调：移 +N 半音"，
        以及输出音高是否回到 120Hz 以上。

3b 伴奏异常
  根因：这是功能缺失，不是 bug。「分人声」模式只输出了人声轨，
        **原伴奏压根没被用上，直接被丢掉了**。翻唱的标准流程是
        "只换主唱、伴奏保留原样"，所以听起来就是"伴奏没了"。
  改动：新增混音模块 rvc_cpu/mixdown.py。分人声模式下，换完人声后
        自动和原伴奏合轨：
          · 人声轨先切掉 90Hz 以下（分离出来的人声总带贝斯/底鼓残留，
            不切的话合轨后低频糊成一团；90Hz 在男低音极限 82Hz 之外，基本无损）
          · 声道/采样率/长度自动对齐（分离是分块做的，末尾能差几十毫秒）
          · 按能量比例混合，峰值超 0.98 时整体降幅而不是硬削顶
            （硬削顶会产生刺耳失真，那正是"带电"的来源之一）
  验证：用合成的人声（单声道 200Hz）+ 立体声伴奏（含 55Hz/80Hz bass）
        做合轨测试。结果：输出 PCM_24 立体声、时长精确、峰值自动降到 0.980、
        伴奏的 55Hz bass 完整保留。


【4】朗读功能完全不可用
--------------------------------
根因：**安装包残缺**。2.0.2 的包里 runtime\_tts_libs 目录条目数为 0 ——
      文字转声音的组件根本没进包，所以一点就失败。

改动：
  · 打包后强制核对条目数（这次 3771 条，与源码目录一致）
  · 实际解压一份到临时目录，用包内 Python 跑一遍朗读，确认能出音

验证：解压后的程序实测朗读。
      结果：3.07 秒音频生成成功，自动移调 +11，载体「云希」，索引已加载。
      （质检 52 分偏低是因为测试文本只有 3 秒，短音频本来分数低）


【5】模型选不了，只能用内置那几个
--------------------------------
根因：两个。
  a) 同样是安装包残缺（见第 4 项）。
  b) 界面上没有"重新扫描模型目录"的入口：模型列表缓存在内存里，
     用户自己把 .onnx 拷进 models 文件夹后，界面不会刷新。

改动：
  · 加「刷新列表」按钮（/api/model/refresh），强制重新扫描
  · 缓存从"永久"改成 3 秒超时，手放文件也能被发现
  · 扩展 PyTorch 查找范围（原来只认 3 个硬编码路径，换台机器就找不到
    → .pth 导入失败，而且不告诉用户为什么）。现在会扫常见的
    Python 安装位置，并在找不到时给出具体的三条解决建议
  · 界面显示 .pth 是否可导入（有 PyTorch 才行）

验证：调刷新接口。
      结果：返回模型数正确、torch 状态 True。
      另外把 mp3 改名成 .onnx 冒充模型，确认会被拒绝并说明原因
      （"这个文件其实是 MP3 音频，不是音色模型"）。


【怎么用这个新包】

1. 解压整个压缩包（别在压缩包里直接双击运行）
2. 双击「启动界面(Plus).bat」
3. 要角色音色：最上面「音色模型」→「导入模型…」，
   把 .pth 和 .index 一起选上（有 .onnx 更好，不用转换）
4. 翻唱：拖音频 → 直接点「开始转换」（会自动测音高定调）
   勾「分人声」的话，转完会自动和原伴奏合轨，输出带"_混音"的成品
5. 朗读：顶部切到「朗读（文字）」→ 打字 → 选情绪 → 点「念出来」

注意：朗读那一步要联网（文字转语音用的是免费在线服务）。
翻唱全程离线。
