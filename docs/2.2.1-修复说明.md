# Plus 2.2.1 —— 导入角色模型后不显示 / 点不了的修复

这一版只做一件事：**修好"导入模型之后，列表里看不到、也没法选"**。

---

## 你遇到的现象

导入一个角色模型（.onnx）之后：

- 弹了"导入失败"，但看不出原因
- 或者列表里干脆什么都没有了
- 再导入一次，还是失败

---

## 一共有四个 bug，叠在一起

### bug 1（最致命）：激活"没有 .index 的模型"会让整个模型列表消失

这是你看到"列表里没法直接调用"的真正原因。

角色模型大多只带一个 `.onnx`，**没有配套的 `.index`**（特征检索文件）。
程序里有个函数负责返回"当前模型的三件套路径"，它对 index 是这么写的：

```python
"idx": os.path.join(MODELS, name + ".index") if name else ""
```

**不管文件在不在，都把路径拼出来交出去。** 上层拿到这个不存在的路径去读文件大小：

```python
"mb": round(os.path.getsize(idx) / 1024 ** 2, 1)
```

直接抛 `FileNotFoundError`。

而这个 `meta()` 是**整个界面的数据源** —— 它一崩，`/api/meta` 只返回一句错误，
界面拿不到 `model_list`，于是：

- 模型列表空了（明明文件在 models 目录里）
- 当前模型显示不出来
- 什么都点不了

**修复**：`paths_for()` 只在 index 文件真的存在时才返回它；
`meta()` 里再加一层 `os.path.isfile` 判断。

顺手把"附加信息"（分离引擎探测、硬件探测）也包进 try ——
这些只是给界面做提示用的，缺了顶多少显示一行，但**不该让模型列表跟着一起消失**。

### bug 2：导入成功后不清暂存区 → 第二次导入必然失败

导入是两步：先把文件传到 `_工作区\_导入暂存`，再从这里装进 `models`。

原来的清暂存代码在**成功路径的末尾**，一旦中途失败（比如验证不过），
文件就留在暂存区里了。下次导入时：

```python
pth = [f for f in files if ...]
onnx = [f for f in files if ...]
base = name or (pth[0] if pth else onnx[0])     # ← 取"目录里第一个"
```

拿到的是**上次残留的文件**。结果要么把 A 模型当成 B 装进去，
要么因为"目标已存在"直接报错。

**修复**：
- 暂存区清理移进 `finally`，**成功失败都清**
- 选源文件改成**按名字匹配**，不再取"目录里第一个"

### bug 3：同名模型一律报错，用户不知道怎么办

```
models 里已经有「姬子」了。先把那个模型删掉，或者给这个模型换个名字
```

这条提示对开发者是清楚的，对使用者是死路 —— 他不知道去哪删、怎么改名。

而且**重复导入同一个模型**（重装、换机器、手抖点两次）是最常见的情况。

**修复**，分三种情况：

| 情况 | 处理 |
|---|---|
| 同名且**内容完全相同** | 不重复占磁盘，直接切成"使用中" |
| 同名但内容不同 | 自动存为 `姬子(2)`，**不覆盖**原来的 |
| 没有同名 | 正常导入 |

内容比较用 SHA-256（只比大小会因为不同模型恰好同字节数而误判）。

### bug 4：失败只显示"导入失败"，真实原因被藏起来

服务端把真实异常放在 `state["error"]`，但界面只显示 `state["msg"]`，
而 `msg` 被写死成"导入失败"。

**这就是为什么你只看到"失败"两个字，无从下手。**

**修复**：出错时界面直接显示 `s.error` 的完整内容。
现在你会看到类似：

```
这个模型加载不了：[ONNXRuntimeError] : 10 : INVALID_GRAPH : ...
```

## 另外顺手修的两个小问题

**清理半成品不能用 `os.remove`**

失败时要把装了一半的文件清掉。原来用 `os.remove`，
但在本机环境下删除会被改写成"移入回收站"，
回收站不可用时会直接 fail-closed 抛异常，结果**文件留在原地**，
下次导入又报"已存在"。

改成 `shutil.move` 挪到 `_导入失败/` 和 `_导入废件/` 目录，不依赖删除。

**重复导入同一模型时列表不刷新**

界面靠"导入的模型名变了"来判断要不要刷新列表。
重复导入同一个（内容相同会复用）时名字没变，列表就不刷，
用户以为没导入成功。现在改成"导入结束就刷"。

## 验证结果

写了 5 个场景的自动化测试，13 项断言全过：

| 场景 | 结果 |
|---|---|
| 干净导入 → 出现在列表、自动切换、暂存清空、registry 已登记 | ✅ 5/5 |
| 再导入另一个 → 两个都在、切换到新的 | ✅ 3/3 |
| 重复导入同一个 → 不多占磁盘、直接切换 | ✅ 3/3 |
| 同名但内容不同 → 明确报错且不覆盖原模型 | ✅ 2/2 |
| 用导入的模型跑一次转换 → 真的能调用 | ✅ 2/2 |

回归测试：端点 21/21、队列全过、修复专项全过。

## 如果你之前导入失败过

不用管，**直接重装这一版，然后重新导入一次就好**。

之前失败可能在 `models` 目录里留下了半截文件，或者 `_导入失败/` 里有残件。
这些不影响使用（列表只扫 `.onnx`，子目录不扫），但想清理的话可以手动删掉：

```
models\_导入失败\
_工作区\_导入废件\
```

如果列表里出现一个能看见但选不了的模型，用界面上的「删除模型」删掉再导入。
