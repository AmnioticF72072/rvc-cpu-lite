声音转换 Plus · 功能范围 / 体积分配 / 优化取舍
==========================================

一、这一版新增了什么
------------------
1. 批量转换
   一次可以选多个文件（也可以整个拖进来），按队列逐个转，界面显示「第 2/5 个」。
   转完的文件都在 输出\ 里，命名规则是「原文件名_Plus.wav」。
   用途：一次把一整张专辑的人声轨过一遍，不用守着点。

2. 设备选择（CPU / GPU）
   界面上三个选项：自动 / 只用 CPU / 用 GPU。
   · 自动：装了 GPU 加速包就用，没装就纯 CPU —— 这是默认值，普通人不用管
   · 只用 CPU：怀疑显卡驱动有问题时用，最稳
   · 用 GPU：优先走加速后端，如果没装加速包会**明确提示并自动退回 CPU**，不会报错退出

3. A/B 试听
   转换完可以直接在界面里点「试听原声 / 试听结果」对比。
   以前只能去文件夹里点开听，来回切很麻烦。

4. 取消任务
   转错了、选错文件、发现参数不对，点「取消」，当前块跑完就停。
   已经转完的文件会保留，不会白等。

5. 清空队列
   批量模式下一键清掉已经加入的文件，重新选。

6.（上一版已有，这版保留）去和声 Karaoke、智能校准、特征检索。

7.（Plus 1.2 新增）音色模型库：导入 / 切换 / 删除
   界面最上面多一张「音色模型」卡片：
   · 导入模型…：拖入 .pth（本机有 PyTorch 就自动转 ONNX，进度可见）或
     .onnx（连同名 .json），.index 可选一起放
   · 多个模型并存，点一下切换；删除有确认，且不允许删掉最后一个
   · models\registry.json 记录当前模型；v1 模型和定长帧数太小的模型会被
     明确拒绝并说明原因（这两类跑起来会出错误结果，不如不让导）
   · .pth→.onnx 转换用随包的 tools\_rvc_export_lib（官方 RVC 2.2 模型代码，
     ~200KB，MIT 许可见 NOTICE.md），不依赖外部仓库
   体积代价：代码 +200KB。之前"换模型要手动改名覆盖"，现在是一条导入的事。


二、体积分配（上限 2GB，实际 1.14GB）
--------------------------------
打包前的实际占用（2026-10-23 实测）：

    项目                              体积        占比    说明
    ───────────────────────────────────────────────────────────
    rmvpe.onnx                       344.9 MB    30%    基频提取，最大的一块
    vec768_dyn.onnx                  360.2 MB    32%    ContentVec 特征提取
    myvoice51.index                  184.4 MB    16%    特征检索索引（61225 条 × 768 维）
    myvoice51.onnx                   121.5 MB    11%    变声主模型（HiFiGAN）
    models/sep/5_HP-Karaoke-UVR.pth  120.9 MB    11%    去和声模型
    ───────────────────────────────────────────────────────────
    模型小计                          1132 MB
    代码 + 界面 + 说明                  < 2 MB（含 .pth 转换用的官方模型代码 200KB）
    ───────────────────────────────────────────────────────────
    合计                             ≈1134 MB    还有 ~866MB 余量

为什么能压到这个数（清掉了什么）：

    · myvoice51_CF200.onnx.bak   110 MB   一个临时备份，跟正式模型重复，已归档
    · hubert_v2_768_dyn.onnx     360 MB   和 vec768_dyn.onnx 是同一个 ContentVec，
                                          代码只用后者，重复的那份已归档
    · _工作区 旧缓存             177 MB   分离中间产物 + 上传原件，已归档
    · 几个早期的 RVC 源码副本      15 MB   参考用的，运行时不需要

这四项一共腾出 660 MB。之前是 1.8G，贴着 2G 上限，几乎没余量加功能。

余下的 866MB 怎么用（按性价比排序）：
    1. 想加第二个音色模型   +121MB（主模型）+ 可选 +184MB（索引）；
       或者用界面里的「导入模型…」直接挂别人分享的模型（不占本身体积）
    2. 想装 GPU 加速包      +180MB（onnxruntime-directml，见下）
    3. 想加 32k 轻量模型    +60MB（速度快一倍，音质略降，适合笔记本）
这三样都加也才 1.5GB，仍在 2GB 内。


三、优化取舍（为什么不做某些事）
----------------------------
· 不做 int8 量化
  能把 830MB 压到 ~250MB，但 HiFiGAN 的转置卷积对量化很敏感，实测会掉细节、
  高音发毛。这个工具的核心卖点就是音质，宁可占体积不压。真缺空间的人可以自己做，
  或者用 32k 轻量模型。

· 不做"免安装运行时"（内置 Python）
  虽然技术上能做到（约 +120MB），但目标用户既然会解压文件、会装软件，
  就没必要为"连装都不会"的人再背 120MB。安装步骤已经压到两步：
  装一次 Python（官网下一步下一步），双击 bat。这一条是明确取舍掉的。

· 不塞 ffmpeg
  ffmpeg 能解决 mp3 输入输出，但静态包 +80MB。现在用系统解码库读常见格式，
  读不了 mp3 就让用户先转 wav —— 这个取舍换来了 80MB 空间和更少的兼容坑。

· 不把分离后端（torch）打进包
  torch 要 1~2GB，一旦装进去直接超 2GB。所以分离走"借用已装 torch 的 python"，
  没装就在界面上把这一步灰掉并说明原因，其余功能照常用。

· 界面用本机 HTTP + 浏览器，不用 Electron/Qt
  Electron 起步 +120MB，Qt 要 PySide6 +200MB。用浏览器应用窗（Edge/Chrome 的
  --app）零额外体积，还能用 backdrop-filter 做真毛玻璃。


四、CPU 与 GPU 两种模式怎么兼容
---------------------------
同一份代码、同一个包，区别只在"装了哪个 onnxruntime"：

    基础包            onnxruntime          只有 CPUExecutionProvider
    + 加速包（可选）   onnxruntime-directml 多出 DmlExecutionProvider
                      onnxruntime-gpu      多出 CUDAExecutionProvider

程序启动时这样决定：

    1. 读 ort.get_available_providers()，看有没有 Dml / CUDA / OpenVINO
    2. 界面上选"自动"→ 有加速后端就用，没有就用 CPU
    3. 建 session 时把加速后端排在前面，CPU 永远放最后兜底：
           providers = [DmlExecutionProvider, CPUExecutionProvider]
       意思是：显卡接不了的算子会自动落到 CPU 上，不会崩
    4. 如果加速后端加载失败（驱动太老、显存不够），捕获异常、打印一行警告、
       自动退回纯 CPU —— 用户看到的是"能跑"，不是"报错"

两个刻意的保守决定：

    · RMVPE（基频）永远跑 CPU。它在 GPU 上输出过错误的音高（整段跑调），
      而且它只占总耗时的 5%，不值得冒险。
    · 默认值是"自动"而不是"GPU"。因为大多数用户的机器根本没装加速包，
      默认 GPU 只会带来一堆"为什么报错"的提问。

实测数据（这台机器 i5-10400，纯 CPU，无加速包）：
    RTF 1.69 ~ 2.19（取决于音频长度和是否开检索）
    5 秒素材 11 秒，20 秒素材 34 秒，30 秒素材 54 秒

GPU 能快多少？参考桌面端同模型走显卡的经验，生成器那一段能快 5~10 倍，
但 ContentVec 和 RMVPE 依然是 CPU，整体大约快 2~3 倍（RTF 0.6~0.8）。
这只是量级估计，装完加速包自己跑一次才知道准数。


五、分发方式（夸克 / GitHub）
-------------------------
夸克网盘：整个文件夹压成 rar，一份 ~1.14GB。
          夸克单文件上限够用，但建议分卷（1GB 一卷）避免上传中断要重传。

GitHub：Release 资产上限 2GB，可以直接传整包；
        但仓库里不要放模型（单文件 100MB 限制），
        代码 + 说明走仓库，模型 + 整包走 Release。
